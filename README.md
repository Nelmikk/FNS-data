
# FNS data parser & API

Высоконагруженный ETL-пайплайн для парсинга реестра МСП ФНС и REST API для доступа к обработанным данным.

![scrape demo](https://raw.githubusercontent.com/Nelmikk/FNS-data/refs/heads/main/fns-data-diagram.png)

## О проекте
Проект решает задачу обновления БД данными по организациям МСП и
быстрого получения данных по организациям с помощью внутреннего API.

Пайплайн скачивает самые актуальные архивы, распределяет данные из архива между процессами для парсинга и вставки в БД.

Сначала данные заносятся в shadow-таблицы, далее атомарно заменяет основные таблицы shadow-таблицами.

Благодаря shadow-таблицам внутренний API работает без простоя.
Для API используется отдельный read-only пользователь.

.env-файл для изменения переменных API и парсера.


## Стек
### Backend: Python 3.12, FastAPI, SQLAlchemy 2.0, asyncio.
### СУБД: PostgreSQL 18.
### Инфраструктура: Docker.
### Пасринг: lxml, zipfile, requests, BeautifulSoup, multiprocessing.


## Основные метрики
* ### Объем данных: 24 ГБ xml-файлов, ~19 млн записей в 4 таблицах. 
* ### Время полного цикла обновления данных: ~15-20 минут (скачивание, парсинг, работа с БД).
* ### Нагрузочное тестирование API: 1000 RPS, p50=0.35 сек., p90=0.75 сек. на HDD.


## Принятые архитектурные решения
- **Shadow-таблицы:** Используются для обновления данных. Позволяют избежать блокировок таблиц во время загрузки данных.
Видно только либо старые данные, либо новые;  


- **JSON для ОКВЭДов:** Замена метода хранения данных о дополнительных ОКВЭДах. 
Изначально использовалась классическая табличная запись, однако SELECT запросы формировались на уровне СУБД дольше ожидаемого,
пришлось идти на выгодный компромисс и использовать JSON.
Итог - сокращение количества строк с 30 млн до ~ 5 млн и, таким образом, значительное ускорение SELECT запросов в БД;


- **Multiprocessing + asyncio:** Парсинг - CPU-bound задача, вставка в таблицу - I/O-bound. Соответственно, 
создав несколько процессов с несколькими корутинами, можно почти одновременно парсить данные и вставлять их в БД;


- **Семафоры:** без ограничителя парсинг будет происходить быстрее, чем данные будут загружаться в БД, 
и, чтобы избежать потребление огромного количества оперативной памяти, этим ограничителем выступают семафоры.


- **Read-only пользователь:** API использует отдельного пользователя БД без прав на запись,
любые таблицы, в будущем созданные пользователем, который дал read-only пользователю права на чтение, 
будут автоматически доступны для чтения read-only пользователю.

## Установка

````
# 1. Клонируйте репозиторий.
git clone https://github.com/Nelmikk/FNS-data
cd PWD

# 2. Переименуйте .env.example в .env.
# (ОПЦИОНАЛЬНО) Редактируйте его под себя.
rename "env.example" ".env"

# 3. Запустите проект через docker compose.
docker docker compose -f docker-compose.yaml up
````
